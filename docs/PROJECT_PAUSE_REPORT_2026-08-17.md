# 心屿项目暂停与交接报告

更新时间：2026-08-17
当前结论：**暂停开发，不进入正式实时数字人集成。**

## 一、为什么暂停

本项目的核心产品门槛不是“能播放一段人物视频”，而是同时满足：

1. 保持已经选定的 R13 人物身份；
2. 照片级画质，不出现换脸、换嘴、假牙或下巴漂移；
3. 能由任意实时语音驱动，而不是预录固定台词；
4. 在目标电脑 RTX 4070 Ti SUPER 16GB 上接近实时运行；
5. 能稳定嵌入 16:9 桌面 UI。

截至本报告，现有本地开源方案不能同时达到以上五项。继续堆叠 UI、记忆或云端大模型无法解决人物渲染质量问题，因此在核心体验闸门处暂停是正确决策。

## 三、真实技术验证结果

### 1. LivePortrait

用途：眨眼、轻微点头和待机动作验证。

结果：

- 可以驱动表情和头部姿态；
- 模型内部低分辨率重建会损失眼睛、睫毛、发丝和皮肤细节；
- 整帧驱动不适合本项目的照片级近景人物；
- “高清母图常驻 + 局部眨眼覆盖”可用于轻量待机，但不能解决任意语音口型。

详细说明位于 `agent/xinyu-desktop-foundation` 分支的 `docs/AVATAR_RUNTIME.md`。

### 2. MuseTalk v1.5

用途：对任意中文语音生成口型，并验证实时性能。

本机实测：

- 核心推理：约 33.7 FPS；
- 峰值显存：约 6.7GB；
- 完整 4K 合成导出：约 15.1 FPS；
- 模型实际在人脸约 256×256 的裁剪区域重建，再贴回 4K 画面。

结论：**性能通过，画质失败。**

主要问题：嘴唇明显变厚、牙齿失真、下巴和脸型漂移，人物身份被破坏。即便收窄为 mouth-only 蒙版，仍达不到产品标准。MuseTalk 已从 UI 中撤下，不得作为正式路线。

复现实验脚本：`scripts/avatar/musetalk_fixed_bbox_proof.py`。

### 3. Ditto PyTorch

用途：验证比 MuseTalk 更完整的音频驱动头像方案。

输入：正式 4K 主场景母图与 3.2 秒中文测试语音。

本机实测：

- 成功生成 1920×1080、25 FPS、3.2 秒视频；
- 首次完整运行约 88.9 秒；
- 写帧阶段 80 帧约 20.2 秒，约 4 FPS；
- 人物身份比 MuseTalk 稳定，嘴型不再出现严重厚嘴问题；
- 但整张脸和头发从 4K 明显变软，牙齿与大开口仍有生成感；
- 当前 PyTorch 路径远低于实时速度。

结论：**相对更自然，但画质与速度均未达到产品门槛。**

### 4. 未继续投入的方案

- LatentSync 1.6：官方最低推理显存约 18GB，高于目标电脑 16GB，而且不是低延迟实时路线。
- LiveAvatar：高质量实时版本要求至少 48GB～80GB 显存或多卡 H800，不符合本机部署目标。
- 继续使用预录视频切换：可以做好待机，但不能满足“任意内容实时说话”，不视为核心目标完成。

## 四、已完成的应用能力

即使暂停数字人渲染，仓库中仍保留了可继续利用的基础：

- React/Vite/Tauri 桌面 UI；
- 此刻、对话、回忆、计划和设置页面；
- 本地核心服务与运行时状态；
- 记忆、会话、计划、通知、天气/日历 Provider 框架；
- 本地音乐播放；
- 实时语音运行时生命周期与中断逻辑；
- 本地模型管理基础；
- 当前 R13 身份母图和 4K 主场景母图。

已有分支：

- `agent/xinyu-desktop-foundation`：桌面基础、人物待机与交接文档；
- `agent/voice-runtime-integration`：语音运行时、通知、记忆和 Provider 基础；
- `agent/realtime-avatar-gate`：当前 4K 场景、口型验证脚本和本暂停报告。

## 五、恢复项目的必要条件

只有满足以下任一条件，才建议恢复照片级本地数字人路线：

1. 出现可在 16GB 显存上运行、1080p 25 FPS 以上并显著保真的新模型；
2. 接受云端实时 Avatar 服务及其费用、网络延迟和隐私取舍；
3. 改为可控的 3D/MetaHuman/Live2D 角色，不再要求保持当前照片人物；
4. 升级至 48GB 以上专业 GPU，并接受更复杂的生成式实时视频栈。

恢复前必须先做 5～10 秒独立样片，不允许先开发 UI。验收顺序固定为：身份保真 → 嘴型 → 清晰度 → 实时性能 → 30 分钟稳定性 → 最后接入应用。

## 六、暂停状态

- 项目代码和正式人物资产已保存；
- 不再继续下载或集成数字人模型；
- 不将 MuseTalk 或 Ditto 的失败结果接回 UI；
- 后续可从任一远程分支恢复，但应先阅读本报告再决定技术路线。
