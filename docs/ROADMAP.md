# 产品与开发路线图

路线图按“先形成可信的陪伴体验，再增加模型复杂度”排序。日期在硬件基准和开发人力确定后再排。

## M0：可演示 UI（已完成）

- [x] 16:9 主场景与响应式布局
- [x] 水晶心 Logo 和心跳动效
- [x] 此刻、对话、回忆、计划、更多页面切换
- [x] 音乐、输入、心情、点滴和清单的演示交互
- [x] 生产构建和基础 Worker 测试

退出条件：另一台电脑能从仓库克隆、安装、构建并运行 Demo。

## M1：桌面壳与本地数据

- [ ] 接入 Tauri 2
- [ ] Windows 安装包、托盘、开机启动开关
- [ ] SQLite 数据库与迁移
- [ ] 对话、计划和设置的真实 CRUD
- [ ] 数据导出、导入与一键删除

退出条件：断网后仍能使用 UI、保存计划和浏览历史。

## M2：可打断的实时语音

- [ ] 麦克风权限与设备选择
- [ ] VAD、流式 STT、LLM、流式 TTS Provider
- [ ] WebSocket 事件协议
- [ ] 播放队列与用户插话打断
- [ ] 延迟、错误和设备状态可观测

目标指标（首轮基准，不是承诺值）：

- 用户停止说话到首个回复音频：本地高性能设备争取 1.5 秒内
- 用户插话到停止播报：争取 250 毫秒内
- 连续 30 分钟对话无音频队列失控

## M3：长期记忆

- [ ] 从对话提取记忆候选
- [ ] 用户确认、纠错、置顶和删除
- [ ] FTS5 + 语义检索
- [ ] 回答中显示“为什么想起这件事”
- [ ] 记忆压缩、冲突检测和过期策略

退出条件：角色能稳定记住关键偏好与共同事件，同时用户能完全控制这些记忆。

## M4：动态人物

- [ ] 人物、背景和前景分层
- [ ] 呼吸、眨眼、视线、轻微头部动作
- [ ] 根据说话状态和情绪切换动作
- [ ] 音频驱动口型
- [ ] 对 Live2D 与写实音频驱动肖像进行显存和延迟对比

退出条件：人物在待机、倾听、思考、说话和被打断时都有自然且可恢复的状态。

## M5：主动陪伴与工具

- [ ] 日程、提醒、天气和音乐工具
- [ ] 有频率上限的主动问候
- [ ] 安静时段和勿扰模式
- [ ] 关系状态随真实互动缓慢变化
- [ ] 记忆与计划联动

退出条件：主动行为有明确来源、可以关闭，不使用内疚或依赖诱导文案。

## M6：质量与发布

- [ ] 崩溃恢复、数据库备份和升级迁移
- [ ] CPU / GPU / 内存分档配置
- [ ] 隐私说明、第三方许可和素材权利审查
- [ ] 自动更新与版本回滚
- [ ] 安装包签名和发布流程
